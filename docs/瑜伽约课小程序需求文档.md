# 瑜伽约课小程序（晨蕴瑜伽）需求文档

| 项目 | 内容 |
|---|---|
| 产品名称 | 晨蕴瑜伽（微信后台名称：瑜伽约课工具） |

## 1. 产品概述

### 1.1 产品定位

面向线下瑜伽场馆的**约课管理小程序**，为瑜伽馆提供学员约课、课程排期、会员管理一体化工具。学员通过小程序浏览课表、预约团课/小班/私教课程并管理自己的预约；馆方管理员在同一小程序内完成排课、停课、调课、会员管理及周课表图片发布。

### 1.2 用户角色

| 角色 | 标识 | 权限说明 |
|---|---|---|
| 游客 | 未注册用户 | 可浏览课表与首页，预约时引导注册 |
| 学员（会员） | user_type 为空/普通 | 约课、取消预约、查看统计、参与营销活动 |
| 被屏蔽用户 | user_type = -1 | 被禁止预约（后台拉黑） |
| 管理员 | user_type = 4 | 个人中心显示管理入口，可管理课程与会员 |
| 教练 | coach 表（独立于 user） | 拥有教练主页，由课程排期关联展示（无独立登录端） |

### 1.3 课程类型（class_type 位掩码）

| 类型 | 值 | 说明 |
|---|---|---|
| 小班课 | 1 | 小班约课频道 |
| 私教课 | 2 | 一对一私教预约 |
| 团课 | 4 | 团操大课约课 |

## 2. 用户端功能需求

### 2.1 登录与用户资料

- **FD-101 微信登录**：小程序启动时静默 `wx.login` 获取 code，由后端代理微信 `code2session` 换取 openid 并缓存于本地；openid 为全系统用户唯一标识。
- **FD-102 资料注册/完善**：首次预约前需填写头像与昵称。基础库 ≥ 2.27.1 使用官方「头像昵称填写能力」（chooseAvatar 按钮 + nickname 输入框），低版本降级为 `wx.getUserProfile`。
- **FD-103 头像上传**：头像经 `wx.uploadFile` 上传至后端，存储为 AVIF 格式，返回 URL 用于展示。
- **FD-104 头像失效检测**：微信头像 URL 可能失效（微信返回错误码 -6101），需在个人中心主动探测，失效时弹窗引导用户更新头像。
- **FD-105 登录跳转回源**：登录成功后按 return_url 返回来源页面（支持 tabBar 页与普通页）。

### 2.2 首页

- **FD-201 顶部信息栏**：品牌名 + 竖直轮播展示「实时天气 / 农历日期 / 北京时间（秒级）」，天气与时间调用第三方接口，农历由本地算法计算。
- **FD-202 轮播图**：后端配置的运营位图片（slideshow 表）。
- **FD-203 金刚区功能入口**：后台可配置的功能宫格（约课、私教、数独、商城、公告等，function 表）。
- **FD-204 教练头像墙**：展示全部教练，点击进入教练主页。
- **FD-205 最近约课动态**：展示最近 10 条预约学员头像，营造氛围。
- **FD-206 营销 Banner**：商城 slogan 引导位，点击跳转商城页。
- **FD-207 公告列表**：展示最新 3 条公告标题与相对时间。
- **FD-208 首页数据聚合**：以上内容由单次聚合接口 `/yoga/index` 一次返回。

### 2.3 约课（核心模块）

- **FD-301 多频道约课**：团课 / 小班 / 私教三个独立频道页，按课程类型拉取未来两周课程。
- **FD-302 周视图与日期筛选**：支持「本周/下周」切换 + 横向日期条选择具体某天。
- **FD-303 课程卡片信息**：课程缩略图、时间、教练、课程名、已约人数/容量、同班已约学员头像（点击可放大查看头像与昵称）。
- **FD-304 课程状态机**（前端实时计算，位模式 mode）：

| 状态 | 触发条件 |
|---|---|
| 已完成 | 当前时间超过课程结束时间 |
| 正在上课 | 当前时间处于课程时段内 |
| 准备上课 | 距开课不足 1 小时 |
| 已取消 | 课程被管理员停课（hidden） |
| 已满额 | 预约人数达到容量上限 |
| 可预约 | 正常开放预约 |
| 取消预约 | 当前用户已预约该课 |

- **FD-305 预约操作**：点击预约 → 未注册则先跳登录；调用预约接口；**无有效会员卡时提示「请您购买会员卡」**（当前购卡在线下完成，会员卡扣减逻辑为规划功能，见第 5 章）。
- **FD-306 取消预约**：用户可取消本人预约；**开课前 3 小时内不可取消**。
- **FD-307 屏蔽校验**：被拉黑用户（user_type=-1）无法预约。
- **FD-308 空态展示**：当天无课时显示「假日注意休息」提示。

### 2.4 已约课程管理

- **FD-401 多时间维度筛选**：今天 / 明天 / 本周 / 近一年（历史记录）。
- **FD-402 预约卡片**：课程时间、名称、教练、日期；开课 3 小时内的课程标记「已过期」且不可取消。
- **FD-403 取消预约**：同 FD-306。
- **FD-404 空态引导**：无预约数据时引导去约课页。

### 2.5 教练主页

- **FD-501 教练资料展示**：头像、姓名、简介。
- **FD-502 教练课程预约**：按团课/小班/私教切换，查看该教练近 7 天课程并可直接预约/取消。

### 2.6 公告

- **FD-601 公告列表**：标题 + 相对时间（"x 之前"）。
- **FD-602 公告详情**：Markdown 富文本渲染，支持内容中嵌入视频，含面包屑导航与发布时间。

### 2.7 商城 / 营销

- **FD-701 营销图文页**：展示会员卡售卖图文（标题、slogan、Markdown 正文、更新时间），用于线下购卡转化。
- **说明**：当前为纯内容展示，无在线下单与支付流程（见第 5 章规划）。

### 2.8 个人中心

- **FD-801 用户资料卡**：头像、昵称、**约课次数统计**（团课/私教/小班分类计数）。
- **FD-802 功能宫格**：约课记录入口；收藏课程、会员卡、会员体测、意见反馈为规划占位。
- **FD-803 管理员入口**：user_type=4 的用户显示管理区块（课程、课表、排课、会员），见第 3 章。

### 2.9 附加功能

- **FD-901 数独小游戏**：独立页面，三档难度（简单/一般/困难），完整生成与求解算法，进度本地存储，独立分享文案，用于引流与留存。
- **FD-902 分享能力**：全局支持会话卡片分享 + 朋友圈分享菜单。
- **FD-903 版本更新**：通过 UpdateManager 检查新版本并提示重启更新。
- **FD-904 设备信息上报**：启动时上报设备品牌/型号/屏幕/SDK 版本/平台等，用于兼容性统计。
- **FD-905 自定义 tabBar**：动态底部导航，约课相关页面在「首页/团课/小班/私教」与「首页/约课/已约/我的」两种形态间切换。

## 3. 管理端功能需求

入口位于个人中心，仅 user_type=4（管理员）可见。

### 3.1 课程查询

- **FD-1001 课程列表**：按「今天/明天/近七日/近半月」筛选，展示课程缩略图、教练、时段（上午/晚上）、课程名、剩余名额（"差 N 人" / "已满额"）或"已完成"，含已取消课程。
- **FD-1002 课程详情**：单节课完整信息 + 已预约学员列表。

### 3.2 课程运营操作

- **FD-1003 代学员取消预约**：管理员可在课程详情中删除指定学员的预约（需确认弹窗）。
- **FD-1004 停课/开课**：切换课程 hidden 状态（节假日、教练请假场景）。停课需考虑通知教练与学员、费用排除（当前无推送通知，为待完善项）。
- **FD-1005 修改课程**：修改课程名、教练、开始时间、容量人数、课程类型（需加载全部可选项）。
- **FD-1006 批量排课**：按「课程（支持新增自定义课程名）+ 教练 + 星期（一~日，可多选）+ 课程类型 + 开始/结束时间（9:00 起每 90 分钟一档）+ 人数（8~16 人）」批量生成周期课程；课程或教练不存在时自动创建。

### 3.3 周课表

- **FD-1007 周课表图片生成**：服务端在模板图上以中文字体渲染一周课程与教练名，生成 PNG 图片。
- **FD-1008 课表图分享**：支持全屏预览、下载、转发（发送给学员/发朋友圈）。

### 3.4 会员管理

- **FD-1009 会员列表**：仅管理员可查看全部普通会员（不含管理员），按注册时间倒序，显示相对注册时间。
- **FD-1010 会员详情**：会员资料 + 注册时间。
- **FD-1011 会员约课记录查询**：查询指定会员在时间段内的约课记录（接口已实现，页面入口暂未启用）。

### 3.5 管理员权限

- **FD-1012 权限校验**：管理接口将调用者 openid 传入数据库，在 SQL 层校验 user_type=4 后才返回数据/执行操作。

## 4. 后端功能需求

### 4.1 架构设计

- **FD-2001 瘦后端 + 胖数据库**：Rust(Rocket) REST API 层仅做参数转发与 JSON 响应，业务逻辑集中在 PostgreSQL 数据库函数（fn_*）中，由 SQL 直接产出 JSON（json_agg / row_to_json）。
- **FD-2002 数据库连接**：PostgreSQL + 连接池（deadpool-postgres）。
- **FD-2003 静态服务**：头像等图片资源由静态目录（Nginx 反代）提供。
- **FD-2004 环境配置**：数据库连接、小程序 AppID/Secret、图片目录等通过环境变量配置，密钥不出现在代码中。

### 4.2 核心接口清单

## 5. 业务规则汇总

1. **课程状态规则**：已完成/正在上课/准备上课（开课前 1 小时）/已取消/已满额/可预约，由前端结合当前时间实时计算。
2. **取消限制**：开课前 3 小时内不允许取消预约。
3. **预约校验顺序**：登录态 → 用户黑名单校验 → 会员卡有效性（规划）→ 满额校验 → 写入预约。
4. **停课规则**：hidden=1 的课程对学员端显示为「已取消」；停课应通知教练与学员（通知能力为待完善项）。
5. **会员卡类型（规划）**：周卡（1）、月卡（30 天）、年卡（365 天）、次卡（按次数）；卡首次使用时自动激活计算有效期；预约时扣减次数/记录使用，取消时回退。
6. **管理员鉴权**：管理操作在数据库函数内校验调用者 user_type=4。
7. **约课统计口径**：按 class_type 分类统计用户预约次数。

## 6. 非功能性需求

| 类别 | 要求 |
|---|---|
| 平台兼容 | 兼容微信基础库 2.20+；新旧两套头像昵称获取方案自动降级 |
| 性能 | 首页单次聚合接口返回全部数据；课程列表按需按日拉取；本地缓存 openid 减少登录请求 |
| 安全 | AppID/Secret 仅存于服务端；管理员鉴权在数据库层；头像上传限 10MB（改进项：接口鉴权目前依赖明文 openid，建议增加 token/签名机制） |
| 可观测 | 设备信息统计入库（含正则校验防脏数据） |
| 运维 | 支持自动化部署（SSH 打包上传远程编译）；小程序自动更新提示 |
| 分享 | 全局支持会话与朋友圈分享；课表图支持图片分享 |

## 7. 现状差距与规划建议（重要）

以下为代码分析发现的**未完成/规划中功能**，若以此文档做二次开发需重点关注：

| # | 模块 | 现状 | 建议 |
|---|---|---|---|
| 1 | 会员卡计费体系 | 数据表与扣卡 SQL 已备但被注释，预约未实际扣卡 | 完成周/月/年/次卡激活、扣减、回退逻辑，与在线购卡打通 |
| 2 | 在线购卡/支付 | 无 wx.requestPayment，购卡在线下完成 | 接入微信支付商户号，实现商城下单购买会员卡 |
| 3 | 消息通知 | 无订阅消息/推送，停课无通知 | 接入小程序订阅消息：开课提醒、停课通知、预约成功通知 |
| 4 | 旧接口迁移 | 小班/私教/已约/公告/商城页面调用 `v1/*` 等旧接口，当前 Rust 后端未挂载这些路由 | 统一迁移到 `yoga/*` 接口体系 |
| 5 | 个人中心占位功能 | 收藏课程、会员卡、会员体测、意见反馈仅 UI 占位 | 按优先级逐步实现（意见反馈成本最低可先行） |
| 6 | 图片上传通用能力 | `/yoga/picture` 接口为半成品 | 补全持久化与用途（课程图、轮播图上传） |
| 7 | 会员约课记录页 | 接口已实现、管理页面入口被注释 | 启用页面入口 |
| 8 | 接口安全 | openid 明文传参，无 token/签名 | 引入会话 token 或请求签名 |
| 9 | 教练端 | 教练无独立登录/管理界面 | 视需要增加教练角色账号，查看自己的课表与学员 |
| 10 | 云开发 | 未使用（无云函数） | 维持自建后端方案即可，无需迁移 |
